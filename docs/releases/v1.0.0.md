# Inoculum v1.0.0

Inoculum turns a small group of user-owned computers on a trusted LAN into a
tiny execution pool for independent, finite work.

## Included in v1.0.0

- One `inoculum` binary with `coordinator`, `worker`, and `submit` subcommands.
- Outbound-only workers; only the coordinator listens for Inoculum traffic.
- FIFO task queue with renewable leases, expiry, retry, and reassignment.
- Interactive terminal views with automatic plain-output fallback.
- HTTPS, shared bearer-token authentication, and explicit fingerprint trust on
  first connection.
- Versioned JSON manifests with stable user task keys.
- Bounded `http_probe` tasks and ordered JSON result export.
- Configurable coordinator-wide lease duration and maximum attempts.
- Physical validation with a macOS coordinator and macOS/Linux workers.

## Platform status

- macOS arm64: physically validated.
- Linux amd64: physically validated.
- Windows amd64: compile-tested and path-policy tested; runtime is unvalidated
  and the artifact is experimental.

## Known limitations

- Coordinator queue and job state are memory-only and are lost on coordinator
  restart.
- Delivery is at least once; workloads must tolerate duplicate execution.
- No arbitrary commands, DAGs, containers, plugins, file transfer, distributed
  filesystem, resource-aware scheduling, autoscaling, or persistent services.
- Intended for trusted, user-controlled LANs. Direct public-internet exposure is
  unsupported.
- Release binaries are not signed or notarized.
